# 10 — Tiers / Risk (계약)

> 스택 중립. 판별 기준은 **실사용자·실데이터·되돌릴 수 없는 외부 효과**다 (언어·클라우드 무관).  
> 규범 본문: [`../HARNESS.md`](../HARNESS.md) §2 (R0 / R1).

## 티어 ↔ 리스크 매핑

| 카드 표기 (레거시/편의) | HARNESS 리스크 | 의미 |
|---|---|---|
| **T0** | **R0** experiment | 실사용자·대체 불가 데이터·비가역 외부 효과 없음 |
| **T1** | **R1** operating | 위 중 하나라도 해당 |
| **T2** archive | (운영 종료) | 새 기능 게이트 없음. 읽기·이관만 |

`PROJECT.md`에는 T0/T1 또는 R0/R1 중 하나로 선언해도 된다. 의미는 위 표와 동일해야 한다.

## 게이트 무게 (비례)

| | R0 / T0 | R1 / T1 |
|---|---|---|
| verify | 체크리스트 또는 가벼운 명령 | push 전 `verify` **벽** |
| 사람 게이트 | 요약 확인 | `HUMAN_GATES` 비어 있으면 안 됨 |
| Staging / squash push | 권장 | **필수** (HARNESS §2·§4 Stage 5) |

## 판별 플로우

```
실사용자 있음? → yes → R1/T1
대체 불가 제3자 데이터? → yes → R1/T1
비가역 외부 효과(과금·발송·공개 배포…)? → yes → R1/T1
그 외 → R0/T0
```

플랫폼(Web / App / Other)은 티어와 **독립**이다. 둘 다 SIGN-OFF에 적는다.
